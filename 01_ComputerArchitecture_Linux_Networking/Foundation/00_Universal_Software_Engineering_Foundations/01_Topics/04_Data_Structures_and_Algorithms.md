# Data structures, algorithms and complexity

> **Priority:** Core · **Study window:** 4 · **Approximate focused time:** 12–15 (overlaps with weekly plan)

## Why it is universal

Choose suitable representations, assess tradeoffs and catch inefficient implementations from AI or humans.

## Detailed table of contents / concepts to cover

- [ ] Arrays/lists, maps/dictionaries, sets, stack, queue
- [ ] Trees and graphs: vocabulary and practical representations
- [ ] Linear search, binary search on sorted data and sorting intuition
- [ ] Recursion, iteration and termination
- [ ] Time and space complexity: O(1), O(log n), O(n), O(n log n), O(n²)
- [ ] Hashing intuition, membership vs. repeated scans
- [ ] Profiling with representative input sizes; algorithmic correctness first

## How to learn it

1. Predict time and space complexity before running code.
2. Implement a stack, queue, frequency counter and binary search.
3. Compare list-based lookup with hash-map lookup using generated data.
4. Ask AI for adversarial inputs, then independently validate its complexity analysis.

## Required exercise

Build an indexed task lookup using a list and dictionary; benchmark search with different data sizes and record tradeoffs.

## Independent exit criteria

- [ ] Can choose a basic data structure for a requirement.
- [ ] Can explain why a nested loop may scale badly.
- [ ] Can identify a correct base case for recursion.

## AI collaboration exercise

Ask an AI assistant for an alternative approach, at least three failure scenarios and a code/design review. Validate the suggestions independently, make one targeted improvement and describe what you accepted or rejected and why. Never treat the AI answer itself as evidence of correctness.
