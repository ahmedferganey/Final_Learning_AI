# APIs, integration and interface contracts

> **Priority:** Core overview · **Study window:** 7 and 10 · **Approximate focused time:** 8–12 (overlaps with weekly plan)

## Why it is universal

Systems exchange data across language and team boundaries; predictable interfaces are useful on any track.

## Detailed table of contents / concepts to cover

- [ ] API contracts, data schemas and backward compatibility
- [ ] GET/POST/PUT/PATCH/DELETE conceptual semantics
- [ ] Input validation and stable response/error shapes
- [ ] Pagination and rate limits at introductory level
- [ ] Retries, idempotency keys and failure handling as concepts
- [ ] Boundary tests and documenting a simple endpoint

## How to learn it

1. Write request and response examples before implementing them.
2. Choose one small transport for the capstone: CLI commands, HTTP API or message format.
3. Use HTTP for practice without committing to a web-development specialization.

## Required exercise

Design and test create/list/update operations for a task resource, using JSON examples and defined errors.

## Independent exit criteria

- [ ] Can document an API another developer could consume.
- [ ] Can explain what a breaking contract change is.
- [ ] Can validate and reject malformed input.

## AI collaboration exercise

Ask an AI assistant for an alternative approach, at least three failure scenarios and a code/design review. Validate the suggestions independently, make one targeted improvement and describe what you accepted or rejected and why. Never treat the AI answer itself as evidence of correctness.
