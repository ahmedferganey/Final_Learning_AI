# Git, collaboration and code review

> **Priority:** Core · **Study window:** 1 and 5 · **Approximate focused time:** 8–10 (overlaps with weekly plan)

## Why it is universal

Changes must be traceable, reviewable, reversible and safe to integrate, regardless of specialty.

## Detailed table of contents / concepts to cover

- [ ] Working tree, staging, commit, branch and repository
- [ ] Status, diff, log, restore, switch and merge
- [ ] Remote repository, push, pull, pull request and review
- [ ] Merge conflicts, atomic commits and meaningful messages
- [ ] .gitignore, protecting credentials and avoiding destructive commands
- [ ] Issue descriptions, review comments and change history

## How to learn it

1. Make one small commit for each independently complete change.
2. Use a feature branch and self-review every diff before merging.
3. Deliberately create a harmless conflict in a practice repository and resolve it.
4. Review an AI-generated patch as if it came from an unfamiliar teammate.

## Required exercise

Publish the CLI project with a README, one feature branch, a merged pull request and a documented rollback demonstration.

## Independent exit criteria

- [ ] Can restore a file without losing unrelated edits.
- [ ] Can explain and resolve a simple merge conflict.
- [ ] Can spot secrets and unrelated changes in a diff.

## AI collaboration exercise

Ask an AI assistant for an alternative approach, at least three failure scenarios and a code/design review. Validate the suggestions independently, make one targeted improvement and describe what you accepted or rejected and why. Never treat the AI answer itself as evidence of correctness.
