# Phase 28 — GRC

Phase 28 connects cybersecurity engineering with **governance, business risk, assurance, audit, and compliance**.

Study order:

```text
109 Governance, Risk and Compliance Fundamentals
        ↓
110 Cybersecurity Risk Assessment
        ↓
111 Security Compliance
```

## Phase Goal

By the end of the phase, you should be able to move from:

```text
"We have a security problem."
```

to:

```text
Business objective
   ↓
Risk scenario
   ↓
Risk owner
   ↓
Control objective
   ↓
Control owner
   ↓
Evidence
   ↓
Assessment
   ↓
Residual risk / compliance status
   ↓
Management decision
```

## Course 110 — Cybersecurity Risk Assessment

Core model:

```text
Threat
 +
Weakness / exposure
 +
Asset / business process
    ↓
Likelihood
 ×
Impact
    ↓
Inherent Risk
    ↓ existing controls
Residual Risk
    ↓
Treatment / acceptance
```

Important principle:

> A risk score is a decision aid, not objective truth.

Record assumptions, evidence, uncertainty, and ownership.

## Phase 28 Capstone

For a cloud-enabled company:

1. Define security governance and RACI.
2. Create policy hierarchy.
3. Define risk appetite and acceptance authority.
4. Build 15 cybersecurity risk scenarios.
5. Create a risk register.
6. Build a unified control library.
7. Map controls to NIST CSF + ISO 27001-style requirements.
8. Create a third-party risk process.
9. Run a compliance gap assessment.
10. Create an audit evidence matrix.
11. Create exception and corrective-action workflows.
12. Build an executive risk/compliance dashboard.
13. Define continuous control-monitoring checks.
14. Run management review.

## Completion Criteria

Before leaving Phase 28, you should be able to:

- explain governance vs risk vs compliance;
- write policy/standard/procedure hierarchies;
- define control objectives and evidence;
- distinguish design and operating effectiveness;
- write clear risk scenarios;
- assess inherent and residual risk;
- define treatment and acceptance;
- create a risk register;
- perform a compliance gap assessment;
- map controls across frameworks;
- manage findings and exceptions;
- create audit-ready evidence;
- explain ISO 27001 ISMS foundations;
- build continuous compliance metrics.
